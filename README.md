# Home Systems · 홈시스템 1.6.0

**Minecraft Java 1.20.1 / Forge 47.4.0 이상(47.x) / Java 17**용 아파트 홈시스템 모드입니다.
싱글플레이와 Forge 전용 서버를 지원하며, 별도 라이브러리 모드는 필요하지 않습니다.

## 온라인 다운로드

[**Home Systems 1.6.0 JAR 다운로드**](https://github.com/mchoe5699/Home_Systems_mod/raw/refs/heads/main/releases/1.6.0/homesystems-1.20.1-forge-1.6.0.jar)

Minecraft Java 1.20.1 + Forge 47.4.0 이상(47.x), Java 17용입니다. 서버와 클라이언트에 같은 버전을 설치하세요.
[SHA-256 체크섬](releases/1.6.0/homesystems-1.20.1-forge-1.6.0.jar.sha256)으로 파일을 확인할 수 있습니다.

[새 기본 기기 5종과 실제 게임 화면 보기](docs/product-references.md)

## 설치 및 업데이트

1. Minecraft **1.20.1 Forge**를 설치합니다.
2. 이전 홈시스템 JAR를 제거하고 **`homesystems-1.20.1-forge-1.6.0.jar`**를 `mods` 폴더에 넣습니다.
3. 멀티플레이에서는 **서버와 모든 클라이언트에 같은 버전**을 설치합니다.
4. 크리에이티브 **홈시스템** 탭 또는 서바이벌 조합으로 기기를 구합니다.
5. **단지 대시보드**로 기기를 포함하는 구획을 먼저 만듭니다. 단지 밖에서는 기기가 작동하지 않습니다.
6. 기기를 빈손으로 우클릭하고 **새 번호 설정 화면에서 번호를 입력·저장**합니다. 1.2 이하의 기기도 이 설정을 다시 해 주세요. 이전 임의 기기 번호는 새 동·호 주소로 자동 변환하지 않습니다.
7. 1.3에서 업데이트한 경우에도 도어카메라·도어폰에는 새 **홈 링크** 연결을 해 주세요. 같은 주소를 저장하는 것만으로 내부 기기가 호출되지는 않습니다.

## 형제모델 선택기

**`homesystems:sibling_selector` (형제모델 선택기)**를 들고, 형제모델이 등록된 제품을 우클릭합니다. 선택 화면에서 모델을 누르면 설치된 제품의 모델이 즉시 바뀌고, 현재 모델은 선택 불가로 표시됩니다. 원래 모델로도 돌아갈 수 있습니다.

- 주소·소유자·문 링크·홈 링크·홈 네트워크 설정과 설치 방향은 유지합니다. 선택한 모델은 월드의 블록 상태로 저장되며 다른 플레이어에게도 동기화됩니다.
- 제품과 사용자가 같은 단지 안에 있어야 하며, 제품 소유자 또는 OP 2 이상만 변경할 수 있습니다. 통화 중에는 변경할 수 없습니다.
- 형제모델이 없는 제품은 화면 대신 안내 메시지가 나옵니다. 크리에이티브 홈시스템 탭과 서바이벌 조합을 지원합니다.
- **아직 실제 제품 사진·설명서·형제모델명이 제공되지 않았으므로 배포본에는 실제 제품의 형제모델을 임의로 등록하지 않았습니다.** 앞으로 제품 요청서에 적어 주시는 형제모델을 해당 제품의 선택 목록과 외형 리소스에 함께 등록합니다.
- 이 선택기는 같은 제품 유형 안에서 외형 모델을 전환합니다. 통신 방식이나 기기 종류를 변경하는 도구가 아닙니다. 실제 모델별 기능 차이는 제품 자료에 맞춰 추가합니다.

개발자가 형제모델 목록과 외형을 등록하는 방법은 [형제모델 등록 안내](docs/sibling-models.md)를 참고하세요.

## 하나의 설정 버튼으로 번호 등록

로비폰·인터폰·비디오폰·월패드는 조작 화면에 **관할경비실 및 세대번호(동·호) 설정** 버튼이 하나 있습니다. 누르면 다음 세 항목을 직접 입력하고 **입력한 번호 저장**을 누릅니다.

- **관할 경비실 번호:** 0~9999
- **동 번호:** 0~9999
- **호 번호:** 0~9999

도어카메라·도어폰은 **홈 링크**로 내부 기기를 연결하면 그 기기의 저장된 관할 경비실·동·호 번호가 적용됩니다. 같은 주소만 입력하고 홈 링크를 하지 않은 기기는 호출하지 않습니다.
경비실기는 별도의 **경비실번호 설정** 버튼을 누르고 **경비실 번호 하나(0~9999)**만 입력·저장합니다.

**0도 유효한 번호입니다.** 빈 입력은 저장할 수 없고 음수·10000 이상은 서버에서도 거부합니다. 앞의 0은 숫자로 처리하므로 `0001`과 `1`은 같은 번호입니다.
번호는 월드에 저장됩니다. 설치자 또는 관리자(OP 2 이상)만 변경할 수 있고, 통화 중에는 주소를 바꿀 수 없습니다.

같은 세대에 비디오폰·월패드·인터폰을 함께 설치해 **같은 관할 경비실·동·호 번호를 중복 등록**할 수 있습니다. 경비실 번호는 다른 단지에서 재사용할 수 있습니다.

## 세대 호출 규칙

- 양쪽 기기와 조작하는 플레이어는 **같은 단지·같은 차원**에 있어야 합니다.
- 경비실을 제외한 기기끼리는 **관할 경비실 번호가 같아야** 연동됩니다.
- 일반 로비폰은 **자기 동 번호와 같은 동**의 세대만 호출합니다.
- 단지 외곽 출입용 로비폰은 **동 번호를 `9999`로 설정**합니다. 이 로비폰은 호출할 동·호를 입력해 같은 단지의 어느 동이나 호출할 수 있습니다. `9999`는 로비폰의 동 제한만 해제하며 단지·관할 경비실 조건은 유지됩니다.
- 도어카메라·도어폰의 **우리 세대 호출벨**은 **홈 링크로 직접 연결한** 같은 동·호의 내부 기기만 호출합니다. 다른 동·호를 요청하는 패킷을 보내도 서버가 자기 세대 주소를 사용합니다.
- 같은 주소의 내부 기기들은 함께 울립니다(한 번에 최대 64대). **먼저 응답한 한 기기만 연결**되고 나머지는 대기 상태로 돌아갑니다.
- 한 내부 기기에서 거절하거나 그 기기를 부숴도 다른 내부 기기의 호출은 유지됩니다. 다른 기기에서 응답할 수 있습니다.

### 예: 경비실 1번, 101동 1203호

1. 경비실기에 **경비실 번호 `1`**을 저장하고 **근무중** 상태로 둡니다.
2. 101동 로비폰에 **관할 경비실 `1`, 동 `101`, 호 `0`**을 저장합니다.
3. 세대의 비디오폰·월패드·인터폰에 **관할 경비실 `1`, 동 `101`, 호 `1203`**을 저장합니다.
4. **홈 링크**로 내부 기기를 선택한 뒤 세대 현관의 도어카메라·도어폰을 선택합니다. 내부 기기가 여러 대면 각 기기를 선택해 같은 외부 기기에 연결합니다. **`1 / 101 / 1203`** 주소도 적용됩니다.
5. 로비폰 조작 화면에서 **호출할 동 `101`, 호출할 호 `1203`**을 입력하고 **세대 호출**을 누릅니다. 또는 도어카메라·도어폰에서 **우리 세대 호출벨**을 누릅니다.
6. 내부 기기 중 하나에서 **응답**을 누릅니다. 도어카메라의 경우 응답 전에도 비디오폰·월패드에서 **영상 화면**으로 방문자를 볼 수 있습니다.
7. **채팅** 버튼을 누르거나 화면을 닫고 **T키**로 대화합니다. 연결된 기기의 8블록 안에서 일반 채팅이 인터폰 대화로 바뀝니다. 내 기기 8블록·상대 기기 16블록 안의 **같은 단지 플레이어**에게 전달되고 월드 전체로 방송되지 않습니다. `/intercom 메시지`도 사용할 수 있습니다.
8. **도어 링크**로 로비폰과 공동현관 문, 내부 기기와 세대 현관 문을 연결합니다. **문 열기**를 누르면 실제 문이 열립니다. 로비폰과 통화 중에는 상대 로비폰의 문을 열고, 도어카메라·도어폰과 통화 중에는 응답한 내부 기기에 연결한 문을 엽니다. 기존 5초 레드스톤 문 열림 신호도 유지됩니다.
9. **종료**를 누르면 일반 채팅으로 돌아갑니다. 화면만 닫아도 통화는 유지됩니다.

## 관할 경비실 우선 연결과 부재·외출 우회

경비실기의 조작 화면에는 **근무중 / 부재 / 외출** 상태 버튼이 있습니다. 설치자·관리자만 바꿀 수 있고 상태는 월드에 저장됩니다. 부재·외출로 변경하면 해당 경비실기의 진행 중 통화도 종료됩니다.

- **관할 경비실 우선 호출**은 설정한 번호의 **근무중** 경비실기를 먼저 호출합니다.
- **다른 경비실 번호를 입력해서 호출**하거나 자동으로 우회하는 것은, 같은 단지에 등록된 **관할 번호의 모든 경비실기가 명시적으로 부재 또는 외출인 경우에만** 가능합니다.
- 관할 경비실이 **단순 통화 중, 청크 미로딩 또는 미등록**인 경우는 부재로 간주하지 않습니다. 이 사유만으로 다른 경비실로 우회할 수 없습니다.
- 부재·외출 상태는 저장되므로, **이미 부재·외출로 설정한 경비실**의 청크가 내려가더라도 그 상태에 근거한 우회는 가능합니다.
- 다른 경비실도 같은 단지 안에 있어야 하며 **근무중·청크 로딩·통화 가능** 상태여야 합니다. 부재·외출인 대체 경비실은 호출하지 않습니다.
- 관할 경비실이 근무중으로 복귀하면 우회 조건이 없어집니다. 조건을 잃은 기존 우회 연결도 종료됩니다.

경비실이 없다는 이유로 임의의 다른 경비실이 우선 연결되지 않습니다. 우회를 쓰려면 관할 번호를 정확히 등록하고 실제 경비실기에서 부재·외출을 설정하세요.

## 도어 링크 — 기기와 실제 문 연결

아이템: **`homesystems:door_link` (도어 링크)**

1. 도어 링크를 들고 **비디오폰·월패드·인터폰 또는 로비폰**을 우클릭해 선택합니다.
2. 연결할 **문**을 우클릭합니다. 문의 윗부분·아랫부분 모두 선택할 수 있습니다.
3. 선택한 기기의 **문 열기** 버튼으로 연결된 실제 문을 엽니다. 통화 중이 아니어도 자기 기기에 연결한 문은 열 수 있습니다.
4. 같은 도어 링크로 기기를 선택한 뒤 문에 **Shift+우클릭**하면 그 연결만 해제합니다.

목재문·철문 및 `DoorBlock` 방식의 문을 지원합니다. 양문은 두 문을 각각 연결하세요. 다락문·울타리 문은 대상이 아닙니다.
기기당 **최대 16개 문**, 같은 단지·차원 안의 **64블록 이내**에서 연결할 수 있습니다. 설치자·관리자 권한이 필요합니다.
문을 새로 열면 **5초 후 자동으로 닫힙니다**. 이미 수동으로 열려 있던 문은 자동 닫기로 변경하지 않고, 레드스톤으로 계속 열린 문도 강제로 닫지 않습니다.
문 열림은 실제 블록 상태이므로 다른 플레이어도 밖에서 볼 수 있습니다. 연결과 자동 닫기 예정 정보는 저장됩니다. 청크를 강제 로드하지 않습니다.
로비폰 통화에서 문을 열 때는 공동현관을 우선하며 세대 내부 문을 함께 열지 않습니다.

## 홈 링크 — 내부 기기와 현관 기기 연결

아이템: **`homesystems:home_link` (홈 링크)**

1. 내부 기기에서 관할 경비실·동·호 번호를 먼저 입력하고 저장합니다.
2. 홈 링크를 들고 **비디오폰·월패드·인터폰**을 우클릭해 선택합니다.
3. 연결할 **도어카메라 또는 도어폰**을 우클릭합니다. 내부 기기의 저장된 주소가 외부 기기에 적용되고 두 기기가 연결됩니다.
4. 같은 세대의 내부 기기를 여러 대 호출하려면 각각 선택해 같은 외부 기기에 연결합니다. 외부 기기 한 대당 **최대 16개** 내부 기기를 연결할 수 있습니다.
5. 연결을 끊으려면 홈 링크로 내부 기기를 선택하고 외부 기기에 **Shift+우클릭**합니다. 해당 연결만 해제됩니다.

같은 단지·차원, 64블록 이내에서 설치자·관리자만 연결할 수 있습니다. 통화는 종료한 뒤 연결하세요.
다른 세대의 내부 기기를 선택해 외부 기기에 다시 연결하면 외부 기기의 세대 주소와 기존 연결 대상이 새 세대로 바뀝니다.
같은 주소여도 홈 링크를 하지 않은 내부 기기는 현관 호출을 받지 않습니다. 반대로 로비폰의 동·호 호출은 기존 주소 방식으로 동작합니다.
내부 기기를 부수고 새 기기로 교체한 경우 홈 링크를 다시 하세요. 단순히 같은 위치·동·호를 쓴 새 기기에 예전 연결이 자동 이전되지는 않습니다.
여러 내부 기기에서 현관 문을 열려면 **각 내부 기기에도 도어 링크로 같은 문을 연결**하세요.

## 제품 사진·사용설명서 기반 외형

기본 5종은 공식 제품 사진·제원·설명서를 참고해 가로 비디오폰, 좁은 무화면 인터폰, 터치 월패드, 카메라·키패드 로비폰, 기울어진 탁상 경비실기로 재제작했습니다. [참고 제품과 구현 범위](docs/product-references.md)를 확인하세요. 특정 제조사 모델의 모든 기능을 그대로 복제한 것은 아닙니다. 사용자가 제공할 특정 제품 사진·설명서·요청서에 따른 개별 모델 제작은 계속 지원합니다.

### 제품 전면 조작 (1.6.0)

- **로비폰:** 화면의 동·호 입력란을 클릭한 뒤 실제 제품 위치의 숫자 키패드로 입력합니다. `*`는 한 글자 삭제, `#`는 동에서 호로 이동/호출입니다. 하단 호출 버튼으로도 호출합니다. 관할 경비실·종료 버튼도 있습니다.
- **비디오폰:** 왼쪽 수화기를 클릭해 들거나 내려놓습니다. 수신 중 들면 응답하고 내려놓으면 종료합니다. 화면 아래의 현관 확인·경비실·문열림·메뉴 버튼이 작동합니다.
- **인터폰:** 수화기로 응답·종료하고 아래 두 버튼으로 관할 경비실 호출·문열림을 합니다. 영상 화면은 없습니다.
- **월패드:** 화면 내부의 현관 확인·경비실·홈 네트워크·응답·문열림·종료 버튼을 터치합니다. 홈 네트워크에서는 연결한 조명·문·가스·기타 릴레이를 제어합니다.
- **경비실기:** 탁상 받침대 위에 설치되는 형태입니다. 화면의 동·호와 숫자 키패드로 세대를 호출하고, 수화기로 응답·종료합니다. 화면의 근무중/부재/외출과 문열림 버튼도 작동합니다.
- **현관 확인:** 자기 세대와 홈 링크된 도어카메라가 있을 때 30초 동안 실제 영상을 봅니다. 같은 버튼을 다시 누르면 끕니다. 도어폰은 영상이 없으며 영상 확인만으로 통화가 시작되지 않습니다.
- **외부 표시:** 수화기의 들기·놓기, 통화 표시등, 실제 카메라 영상, 월패드 홈 제어 상태가 월드의 제품에서도 보입니다. 수화기선은 없습니다.
- **통신 방식:** 하단의 기존 번호 설정 버튼 안에서 STAR/BUS를 저장합니다. 기존 기기의 기본값은 STAR입니다. 서로 다른 방식은 같은 단지라도 호출·홈 링크·영상 확인·경비실 우회가 불가능합니다. 기존 연결 정보는 보존되지만 방식이 다르면 작동하지 않습니다.
- **로고:** [별도 PNG 리소스](docs/logos.md)로 교체할 수 있습니다. SVG를 보내주시면 PNG로 변환해 적용합니다.

번호 설정 버튼은 제품 하단에 공통으로 유지합니다. 로비폰·비디오폰·인터폰·월패드는 하나의 버튼에서 관할 경비실·동·호를, 경비실기는 경비실 번호를 직접 입력하고 저장합니다. 사진을 그대로 붙인 장식이 아니라 해당 부품 위치를 클릭해 조작합니다. 버튼에 마우스를 올리면 기능이 표시됩니다.

## 영상 화면과 통화 범위

- 비디오폰·월패드·경비실기의 영상 화면은 실제 상대 기기 앞의 블록·플레이어·바닐라 생명체를 보여 줍니다. 도어폰·인터폰은 영상 송출원이 아니므로 영상 화면에 **상대 기기는 영상 없음**이 표시됩니다.
- 영상은 약 **초당 4회**, 기기 중심 **17×9×17블록 중 같은 단지 범위**를 갱신하는 보안 카메라 방식입니다.
- 액체·파티클·날씨·표지판 글씨·특수 블록 엔티티 렌더링·다른 모드의 생명체·장비 외형은 전송하지 않습니다. 화면 조명은 확인하기 쉽게 밝게 표현합니다.
- 양쪽 청크가 로드되어 있어야 합니다. 카메라·호출·지도는 청크를 강제 로드하지 않습니다.
- 무응답 호출은 **30초**, 연결 통화는 **5분** 후 종료됩니다. 서버 재시작 후 진행 중 통화는 유지되지 않습니다.

## 월패드 홈 네트워크

월패드의 **홈 네트워크** 화면에서는 조명·문·가스 밸브·기타 장치를 별도로 제어합니다. 통화와 독립적으로 사용할 수 있습니다.

| 장치 | 아이템 ID |
| --- | --- |
| 조명 릴레이 | `homesystems:light_relay` |
| 문 릴레이 | `homesystems:door_relay` |
| 가스 밸브 릴레이 | `homesystems:gas_relay` |
| 기타 장치 릴레이 | `homesystems:utility_relay` |
| 네트워크 연결기 | `homesystems:network_linker` |

1. 장치 근처에 릴레이를 놓고 램프·철문 등과 레드스톤으로 연결합니다.
2. **네트워크 연결기**로 내 월패드를 우클릭한 뒤 릴레이를 우클릭합니다.
3. 빈손으로 월패드를 열고 **홈 네트워크** 화면에서 각 채널을 제어합니다. 같은 종류의 릴레이는 함께 제어됩니다.
4. 연결기로 릴레이를 **Shift+우클릭**하면 연결이 해제됩니다.

월패드 하나에 **같은 단지·같은 차원, 64블록 이내, 최대 32대**를 연결할 수 있습니다. 설치자·관리자 권한이 필요합니다. 켜진 릴레이는 세기 15 신호를 냅니다.
월패드 청크가 내려가면 최대 1초 안에 꺼지고, 다시 로드되면 저장된 상태를 따릅니다. 월패드를 부수면 연결도 해제됩니다.
**가스는 밸브용 레드스톤 신호입니다. 실제 가스 유체를 추가하지 않습니다.** 기본 상태는 차단입니다.

## 단지 대시보드

**`homesystems:estate_dashboard`**를 들고 허공을 우클릭합니다.

1. 이름을 입력하고 **구획 만들기**를 누른 뒤 지도에서 왼쪽 마우스로 드래그합니다. **한 칸은 16×16블록(청크)**이며 높이에 관계없이 해당 X/Z 영역을 포함합니다.
2. 구획을 클릭하고 **이름 저장**으로 이름을 바꿉니다(1~32자).
3. 첫 단지를 선택하고 **단지 합치기**를 누른 뒤 두 번째 단지를 클릭합니다. **맞닿은 내부 경계만 없어지고 외곽은 그대로**입니다. L자·떨어진 구획을 합쳐도 빈 땅이 채워지지 않습니다.
4. **구획 분리**를 누르고 원래 구획을 클릭하면 별도 단지로 분리되고 경계가 다시 나타납니다. 분리 모드에서는 원래 경계가 점선으로 보입니다.
5. 오른쪽 마우스 드래그로 이동하고 휠로 확대합니다. **내 위치 / 새로고침**으로 현재 위치로 돌아옵니다. 작은 구획 이름은 마우스를 올리면 표시됩니다.
6. 구획을 선택하고 **구획 삭제**를 두 번 누르면 삭제됩니다.

서버에서 로드된 실제 표면 색상을 지도에 표시합니다. 미로딩 지역은 어둡게 표시됩니다.
한 구획 최대 **64×64칸**, 월드 전체 최대 **512개**이며 서로 겹칠 수 없습니다. 생성자는 자기 단지만, OP 2 이상은 전체 단지를 편집할 수 있습니다.
합친 구획은 하나의 단지이며 분리하면 단지 사이 통화와 릴레이 연결의 동작이 차단됩니다. 단지 정보는 저장됩니다.
토지의 설치·파괴 자체를 막는 보호 모드는 아닙니다.

## 서바이벌 조합

기본 통신 기기 7종은 다음 패턴입니다.

```text
철   철   철
레드 중심 레드
철   구리 철
```

철 = 철 주괴, 레드 = 레드스톤 가루, 구리 = 구리 주괴.
중심 재료: 로비폰 **돌 버튼**, 비디오폰 **유리판**, 인터폰 **소리 블록**, 월패드 **네더 석영**, 경비실기 **나침반**, 도어카메라 **망원경**, 도어폰 **종**.
기기를 부수면 아이템은 나오지만 주소·설치자 설정은 초기화됩니다. 릴레이·연결기·대시보드 조합도 포함합니다.

## 개발 및 검증

JDK 17을 설치하고 `JAVA_HOME`을 설정합니다. 체크섬이 고정된 Gradle 8.8 Wrapper를 사용합니다.

```sh
./gradlew build
./gradlew runGameTestServer
./gradlew runClient
```

Windows에서는 `gradlew.bat`를 사용합니다. 배포 파일은 **`build/libs/homesystems-1.20.1-forge-1.6.0.jar`**이며 Forge `reobfJar`를 마친 JAR를 배포합니다.
GameTest는 매 실행 시 테스트 전용 `run-gametest/world`를 초기화합니다. 일반 서버·클라이언트 월드는 건드리지 않습니다.
GameTest는 기존 단지·홈 네트워크·호출·채팅·영상 테스트에 더해, 주소 경계값·저장·관할 일치·9999동·다중 세대 호출·첫 응답·거절·기기 제거·도어카메라/도어폰 구분·경비실 상태·부재 우회·우회 금지를 검사합니다.
도어 링크·홈 링크 아이템의 실제 선택, 위·아래 문 선택, 양쪽 문 블록 열림·자동 닫기, 링크 저장·해제·권한·교체된 기기 거부, 선택한 내부 기기에만 호출하는 동작도 검사합니다.

클라우드에서 서버 테스트만 할 때는 `runGameTestServer -x downloadAssets`로 서버에 불필요한 클라이언트 리소스 다운로드를 생략할 수 있습니다. 프록시·CA 신뢰를 올바르게 설정하고 TLS·체크섬 검증을 유지하세요.
텍스처·모델·조합법·번역은 직접 제작했으며, `python tools/generate_assets.py`(Pillow 필요)로 재생성할 수 있습니다.

형제모델 선택기 검증은 모델 상태 변경·원본 복원·설정 유지·권한·거리·소지품·통화 중 차단·카탈로그 재로딩·기기 교체 및 잘못된 목록 거부를 포함합니다.
